# Формат файлів InOutJSON

Файл — один JSON-документ у UTF-8. Коментарі, зайві дані після документа та невалідний JSON заборонено.
Кореневий об’єкт містить рівно три поля:

- `format`: рядок `cosmos-simulation`.
- `version`: ціле число `1`.
- `data`: об’єкт із полями контейнера. Назви полів чутливі до регістру.

Приклад для `Temp`:

```json
{
  "format": "cosmos-simulation",
  "version": 1,
  "data": {
    "coord": { "x": "1", "y": "2", "z": "3" },
    "V": { "x": "0", "y": "0", "z": "0" },
    "a": { "x": "0", "y": "0", "z": "0" },
    "mass": "1000",
    "radius": "10"
  }
}
```

```java
InOut<Temp> file = new InOutJSON<>(Path.of("object.json"), Temp.class);
file.output(object);
Temp restored = file.input();
```

Шлях передається в конструктор; також доступні `input(Path)` та `output(Path, T)`.
Запис замінює вміст файла; батьківський каталог має існувати.
Помилки файлової системи, формату та перетворення даних передаються як `IOException`.
`null` замість об’єкта заборонений. Тип потрібно передавати явно: конкретний контейнер
із конструктором без аргументів або Java record. Абстрактні класи та інтерфейси не підтримуються.
Універсальний файловий клас не перевіряє фізичний зміст значень (масу, радіус тощо).
Gson ігнорує невідомі поля всередині `data`; відсутні поля отримують значення конструктора
або типові значення Java. Перевірка обов’язкових полів — відповідальність валідатора моделі.
Колекції як кореневе `data` не підтримуються: помістіть їх у поле контейнера.

Для терміналу використовується `InOut<String>`: `input()` читає рядок, `output(String)`
виводить текст без автоматичного переносу рядка. Меню та введення вектора доступні
через конкретний клас `InOutTerm`.
